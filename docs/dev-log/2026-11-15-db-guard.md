## The deploy gate

`scripts/ops/bv-deploy.sh` (installed copy `~/bin/bv-deploy.sh`) now, before it stops the clock: refuses when the PR's `build` check is
not SUCCESS, then reads `scripts/ops/harness/db-health/gate.sql` once through the read-only judge (`read-only.mjs`) and refuses when
`gate_ok` is false (beat mean over 2 s in the last 5 minutes, database over 1,500 MB by the catalog, more than 5 sessions waiting on IO)
or the read fails. Nothing is pushed and the clock is not touched. `BV_DEPLOY_FORCE=1 BV_DEPLOY_REASON="why"` deploys anyway and writes
the reason into the push log. After the push and the wind it prints the same read once. `harness.guard.spec.ts` now lists
`bv-deploy.sh` among the scripts that send a file to production (it asks the judge first, as the rule wants).

Decided by default: no beat at all in the last 5 minutes (the clock is already stopped, e.g. after a failed deploy) does not refuse;
the gate's line says `beat none`. The database size is the catalog's page count (`pg_class.relpages`), not `pg_database_size()`,
because that function is volatile and the rule is stable / immutable only; it can lag a few percent behind the disk.

## Judged not worth enforcing, and why

- **Rows touched per run, measured.** The spec checks that a cron job's migration STATES its rows a run, not that the number is true:
  that needs the job run on a production-sized world. The number is read in review, and the gate catches a job that turns out heavier.
- **A full-table scan inside a job** (cause 5). No static reader can tell a scan from an index read; the cost shows in `daily.sql`'s
  cache hit and hot set, and in the beat.
- **A scheduled health job.** Not built, on the owner's brief: it would itself cost the database every run.
- **Polling the gate after a deploy.** One after-read only, as the owner allows; the 30-minute after-check rule stays as it was.
- **The disk burst budget itself.** It is on the Supabase dashboard, not in any table the database can read; the doc says where to look.
- **Frozen files.** Files up to 0418 are history: the spec flags several (0248, 0291, 0292, 0412) only in its history test.
