# Proof 47 red on the nightly: the proof read tomorrow's book, the payer read today's

2026-11-11. Finding: nightly run 42923963630 (2026-11-10 23:30Z) red on
`scripts/db/proofs/47_pirate_merchants.sql`:
`PROOF 47 FAIL: a pirate merchant was founded with no room in the hoard`.

## Verdict: the proof is fragile (it depends on the clock). The game is not wrong.

The proof fails whenever it runs from 21:00 UTC to midnight, and passes at every other hour. It has
nothing to do with which world was built: every one of these runs restored the same kept world
(`329/329 restored from the prefix cache`), so the random world build (0126, 0276, 0010) is not the cause here.

## Cause

Step 4 of the proof ("the gates") wants to show that a founding the hoard cannot pay is refused whole
(`E_HOARD_SHORT`). It does so in two moves:

1. It writes the day's room as fully spent in `public.pirate_spend_day`, for the UTC day of
   `v_t0 + 3 hours` (`v_t0` is `now()`).
2. It calls `public.new_house(... 'PIR' ...)` directly and expects `E_HOARD_SHORT`.

But the payer does not read that day. `public.founding_credit` (0341, the hunk at
`supabase/migrations/20260818000341_pirate_merchants.sql:462`) pays through
`public.pirate_pay('PIRATE_FOUND', p_delta, now(), ...)`: the wall clock. `public.pirate_spend_room`
(0339, `20260818000339_pirate_ships_sail.sql:307`) then reads the row of the UTC day of `now()`.

Before 21:00 UTC, `now()` and `now() + 3 hours` are the same UTC day, so the spent row is the payer's
row and the founding is refused. From 21:00 UTC on, `now() + 3 hours` is tomorrow: the proof spent
tomorrow's room, the payer still had today's whole room (about 5,000,000 d. less the 252,500 of the first
founding), the probe house was founded, and the proof raised its own failure line.

## The fix (proof only)

`scripts/db/proofs/47_pirate_merchants.sql`, step 4, the direct-payer probe:

- before the probe, when the wall clock's UTC day is not the day of `v_t0 + 3 hours`, the wall clock's
  day is written fully spent too (its old value kept);
- a new assert: `public.pirate_spend_room(now())` must be 0 before the probe, so the probe can never
  again pass or fail for a reason other than the room;
- after the probe, the wall clock's day is put back, so the second founding (step 5) is paid as before.

Nothing the proof proves was loosened: the same 12 markers, the same `E_HOARD_SHORT` expectation, the
same "no house left behind" check, and one assert added.

## Is anything wrong in the game? No, with one thing to know.

`public.pirate_found(p_now)` judges the room on the day of `p_now`, and the payer books the spend on the
day of `now()`. In live play these are the same moment: the job `public.tick_pirate_merchants` runs with
its default `p_now = now()`. They differ only when a caller passes another time, which only proofs do.
So no pirate merchant can be founded past the hoard's room in live play by this path. If a later slice
ever calls `pirate_found` with a time that is not now, `founding_credit` would need the caller's time
passed down; that is a note, not a request.

## Not proven

- The fixed proof was not run in the real 21:00-24:00 UTC window; the shifted copies stand in for it.
  The first nightly after the merge is the real check.
- Only proof 47 was run. Other proofs were not searched for the same pattern (a book row written for
  `now() + N hours` while the code under test reads `now()`).
- The full proof suite and the from-zero build were not run locally (the rule); CI is the full proof.
