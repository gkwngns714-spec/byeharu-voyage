## What it adds

| piece | what |
|---|---|
| `port_treasury.restock_rate`, `.restock_day` | the harbour's rate for ONE game-day, and the day it was set for. Null until lit. |
| knobs | `restock_by_investment` **false** (the dark switch), `restock_r0` 0.03, `restock_r1` 0.30, `restock_i_half` 500000, `invested_half_life_hours` 72 |
| `restock_formula(I)` | `r0 + (r1 − r0) × I / (I + I½)`, 4 places |
| `restock_lit()` | knob AND `economy_closed()` — the one gate |
| `restock_rate(port)` | THE one reader. Not lit: `stock_regen_fraction`. Lit: the day's stored rate (a harbour the job has not reached: `stock_regen_fraction`) |
| `invested_decay()` | `I ← round(I × 0.5^(1/72))` on tracked rows |
| `restock_day(day)` | lit only: once per game-day per harbour, `restock_rate := restock_formula(I or 0)` |
| `tick_city` (3 hunks) | roll calls `invested_decay()`; the roll's purse update adds the hour's SHARE + DONATION to `invested` (null stays null); step 3b calls `restock_day(today)` (errors go to the receipt's `errors`) |
| `tick_market_drift` (2), `price_path` (1) | read `restock_rate(port)` instead of the knob |

## Lighting it (main session, later)

`update public.world_config set value = 'true'::jsonb where key = 'restock_by_investment'`, then the next hourly
`tick_city` sets every harbour's rate (a harbour is on `stock_regen_fraction` until then). Off again by the same update.
Needs `economy_closed` true (it is, since 06:52 UTC).

## Where the design did not fit the live bodies

1. **"Goes live when it deploys" is wrong.** The economy is already closed on prod, so a gate on `economy_closed()`
   alone would have lit E5 on deploy. A knob (`restock_by_investment`) is the dark switch.
2. **"`invested` null" no longer holds on prod.** E7's switch seeded all 246 rows. The roll therefore writes `invested`
   from the day this deploys (decay + SHARE + DONATION), lit or not, so it is current when the knob turns. Nothing reads
   it while dark. This is the one visible change.
3. **`depth_mult` / max stock is NOT built.** §3's owner override (max stock moves with investment, ±10 %/day step) needs
   `stock_target` re-cut in `mid_terms`, `price_path`, the glut and the quote path; the slice table's E5 row does not list
   it. Left as slice E5b. Say the word and it is cut next.
4. `tick_city` does not reference `stock_regen_fraction`; the readers are `tick_market_drift` and `price_path`.
