# 2026-10-27 — Economy E6b: a city wants what it lacks (owner row 214, `osn-e6b-wants`, migration 0255)

> *"for each city, the trade good that city needs, and the city will pay much more money. this should be for every
> city, 1~3 trade goods."* (owner, 2026-10-26, docs/CLOSED_ECONOMY.md §4b)

**Lands DARK** behind `city_wants` (false). Turning it on is the owner's call:
`update public.world_config set value = 'true' where key = 'city_wants'`.

## What it adds

| piece | what |
|---|---|
| `public.city_wants` | append-only log of every draw: (period, harbour, good, mult, cap, nearest_nm, weight). Server-only |
| `public.city_want_fills` | units each city bought at its want price this period (the cap's tally). One writer: `cmd.do_sell` |
| knobs | `city_wants` false, `want_mult` 2.0, `want_cap_pct` 0.10, `want_min_nm` 1500, `want_regional_weight` 1.5, `want_period_seconds` 1440 |
| `public.wants_lit()` / `want_period(ts)` | the gate (knob AND `economy_closed()`) / the wants' one clock |
| `public.wants_draw(now)` | lit, once a period: every harbour draws 1 + (I ≥ median) + (I ≥ top quartile) wants by weighted random (md5 of port, period, good: reproducible) |
| `world.want_left(port, good)` | THE one reader: this period's (mult, units left) |
| `world.city_wants_now(port)` | the city's list, for `world.market` |
| `port_goods.want_period` | the walk's marker: the last period a row was drawn (written by `wants_draw` alone; the truth is `city_wants`) |
| `world.quote_priced` (4 hunks) | the row read it already makes also reads the marker; only a row ever drawn asks `want_left`; a sale's first `left` units are priced at mid × mult (one flag test a shelf; the shelf splits where the want runs out). Dark: no extra query |
| `cmd.do_sell` (1) | adds the units sold at the want price to the tally |
| `world.market` (2) | a wanted row carries `wanted` / `wanted_left`; the payload carries `wants`. Both absent when none: dark byte-identical |
| drift job (1) | `tick_market_drift_each_port` calls `wants_draw(now)` first, every 10 min; it draws only when a new period has begun |
| client | City view: "Wanted ×2: Pepper · Silk" / "수요 ×2: …"; a wanted good's quay row says "Wanted ×2" |

Paid from the city purse by the sale itself (`city_pays`): never minted. The empty-purse rule judges the whole total.

## Decided by default (the owner may reverse)

- **Refresh twice a game-day** (`want_period_seconds` 1440), as briefed. §4b's table says "once a day"; the knob holds
  either (2880 = once a game-day, 86400 = once a real day).
- "Sold somewhere ≥ 1,500 nm away" = the good's **nearest maker** is ≥ 1,500 nm away (`port_goods.haul_nm`).
- "Regional wants" = `port_goods.demand > 1` (0066 seeded it from REGIONAL_GOODS.md).
- The cap (10 % of the good's max stock) is per period; past it, the normal price. Two sales at the same instant can
  each see the same units left (small overshoot, never a refusal).
- A short purse shrinks the lot as for every sale; want units are walked first.
- Goods the city's culture refuses are never wanted.
- Stats → Cities' wants list is not in this slice (the city view and the quay rows show them; the log is the table).
