the guard and the switch, and the main session lights it with one `select` (the runbook is below).

- `supabase/migrations/20260818000240_the_economy_is_closed.sql` (0238 and 0239 are in flight elsewhere; the deploy
  renumbers it to the prod head + 1).

The owner wants the economy lit once the minimum safe set is in: E1–E4b (live: 0228, 0229, 0233, 0234, 0236, 0237) plus
E7. E5 (restock by investment), E6 (trades move the price both ways) and E6b (city wants) are not built. Each of them

## What it adds

| piece | what |
|---|---|
| `public.mint_guard(kind, delta)` | THE one judge of new gold. While the economy is closed (and the city purses are lit), a **positive** delta of a **minted** kind (`stats_flow_words.side = 'minted'`: EARNINGS, FOUNDING, GRANT, IMPORT_DEMAND, NPC_REFOUND, SEED) raises `E_NO_NEW_GOLD`. While open it does nothing. Server-only. |
| `public.credit` (1 hunk) | A positive delta goes through `mint_guard` unless `byeharu.paid_by_city = 'on'`. |
| `public.treasury_post` (1 hunk) | A positive delta goes through `mint_guard`, so a city is never paid new gold. The check sits after the existing early return, so with dark purses nothing changes. |
| `public.city_pays` (1 hunk) | When the city's purse really paid (`treasury_post` wrote its row), the house's `credit` runs with `byeharu.paid_by_city = 'on'` (`set_config`, local), and the old value is put back right after. This lets a capital-paid FOUNDING through (0234's `capital_pays` → `city_pays`) and nothing else. If the city wrote nothing, it is the plain credit, as before. |
| `public.economy_close_switch(p_on)` | Owner / service role only (revoked from public, anon, authenticated; not in the client registry). **true:** refused while the purses are dark (`E_PURSES_DARK`). It seeds `port_treasury.invested` = Σ `city_shares.paid` where that is null, sets `economy_closed_at` = now() and `economy_closed_total` = the world total that second (`world.stats_now()` `total`), flips `economy_closed`, and writes one `events` row `ECONOMY_SWITCH` (`player_id` null; payload `closed, at, world_total, invested_seeded, invested`). **false:** sets `economy_closed` false and both records back to null, and writes one `ECONOMY_SWITCH` row (`closed false, at, world_total, closed_at, total_at_close, total_moved`). Asking for the state it is already in answers `{changed: false}` and writes nothing. No money moves either way. |
| knobs | `economy_closed_at`, `economy_closed_total` (both JSON null). |

The `ECONOMY_SWITCH` event has no player, so no player's feed shows it. It is there for the news design
(`docs/NEWS_AND_MARKERS.md` §2.2: "`UPDATE` … and `economy_close_switch` (E7)"). Its N-slice can read the row, or call
`news_post` from the switch.

### Decided by default (the owner may reverse)

- **The drift knobs of §6 (600 s, 0.932, 0.0166) are not set by this switch.** They are §4's price noise and ride with
  E6. `drift_slot_seconds` has 16 readers, and `port_goods.drift_slot` is stored in slot units. Going 900 → 600 → 900
  (a switch-back) would leave every row's slot ahead of the clock, so `tick_market_drift` would not drift any price for
  months. So "switching off restores every knob" means the three knobs this switch writes.
- **`invested` is seeded by the switch** (as §6 says), and only where it is null, so a later re-light keeps whatever E5
  has rolled by then. The switch leaves it alone when it switches off: it is a figure that nothing reads until E5, not
  a knob. Seeded now, it is ≈ the steady state §3 expects (prod: Σ paid 128.5 M over the register).
- **"Lit" for the guard means `economy_closed()` AND the purses lit**, the same test 0234's `founding_credit` makes. So
  a closed economy with dark purses can never block a sign-up, and the switch refuses to close while the purses are
  dark.
- **A negative minted delta is not judged.** None exists, and it is not new gold.
- **No client word for `E_NO_NEW_GOLD`.** No player act reaches it (proven below). If one ever shows up, a writer slipped
  past the guard and needs a fix forward (§7, first row). It shows as the English sentence.

## Every path that still mints, and what happens to it while lit

| kind | writer | lit |
|---|---|---|
| `EARNINGS` | `public.city_day` | **Not posted** (0233's gate). The guard would refuse it if it were. |
| `IMPORT_DEMAND` | `cmd.do_sell` | **Not posted.** 0233 makes the premium total − round(total / 1) = 0, and `treasury_post` returns at 0 before the guard. The SELL is paid whole by the city. |
| `SEED` | `public.city_treasury_switch(true)` (only when no SEED was ever posted; prod has them) and every new-harbour migration (0217's pattern) | **Refused** (`E_NO_NEW_GOLD`). A new harbour must start at 0 and be funded by `CROWN_AID` from its capital (§2.1). The next new-harbour migration has to be written that way. |
| `FOUNDING`, player sign-up | `cmd.found_house` → `new_house` → `founding_credit` | **Routed through a city.** The country's capital pays (`capital_pays` → `city_pays`, `paid_by_city`). If the capital is short, it calls the gap from its realm (`CROWN_CALL`). If the realm is short, the world's richest harbour pays it. |
| `FOUNDING`, merchant founding | `npc_found` → `new_house` → `founding_credit` | Routed the same way. |
| `FOUNDING`, tuition | `npc_fix_hull_skills` → `founding_credit` | Routed the same way. |
| `FOUNDING`, last fallback | `capital_pays`'s plain `credit` when **no harbour in the world** has the surplus | **Refused.** Not reachable today: 131 harbours can each pay a whole founding, and the richest has 49.9 M of surplus (prod check 6). |
| `GRANT` | none (one-off 0172) | **Refused** if anything ever writes it. |
| `NPC_REFOUND` | none (retired 0213) | **Refused** if anything ever writes it. |
| `CROWN_AID`, `CROWN_TAX`, `CROWN_CALL`, `CAPITAL_GIFT`, `PORT_FEE`, all costs | city ↔ city / company ↔ city | `moved`: never judged. |

How the search was done. Every live body in `public`, `cmd`, `world` and `voyage` was searched for each minted word,
and for every call to `credit`, `treasury_post`, `city_pays`, `pay_city`, `capital_pays` and `founding_credit`, with
both literal and pass-through kinds. Only `credit` writes `ledger` (`npc_compact` re-summarises rows, it moves no
purse). Only `treasury_post` writes `treasury_flows`. The bodies that UPDATE `port_treasury` (`city_day`, `tick_city`,
`city_treasury_switch`) roll flows or set reserves; they create no money.
