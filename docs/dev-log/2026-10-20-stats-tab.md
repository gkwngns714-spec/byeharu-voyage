### The owner's rule for city figures (2026-10-20, relayed by the main session; MUST be built in)

*"a statistic info of a city is added only when you invest certain amount."* City-level statistics are
INTELLIGENCE a company buys by investing in that city.

- **Public to everyone:** the world Overview (money by holder, minted vs moved, volume); the per-good WORLD index
  (aggregated across ALL markets, so no single city can be read out of it); the merchants summary; Me and the
  leaderboard (rank and name only — never another company's purse, decided by default).
- **Gated per city by the VIEWER'S OWN stake in that city.** The one authority for "how much has this company
  invested here" is the share register `public.city_shares` (0123): `sum(paid) where player_id = viewer and
  port_id = city` — the same sum `world.holdings` (0176) and `world.town_hall`'s `you` print. Read it; keep NO
  second tally. (`public.port_influence` / `investor_rank` (0191) is a different thing — the country race's
  giving points — and is NOT the stake.)
  - **Tier 0** (nothing invested): the city appears LOCKED — name, flag, "Invest X 🪙 to see this city's figures",
    with how much more is needed.
  - **Tier 1** (≥ `stats_city_tier1` 🪙): the city's overview — purse trend, income vs spending, taxes, the goods it
    buys and sells most.
  - **Tier 2** (≥ `stats_city_tier2` 🪙): full detail — every good's price history, stock vs normal, bought/sold per
    period, scarcity and glut.
  - The thresholds are KNOBS in `world_config`. The server enforces the gate: the read RPC returns a city's figures
    only at the tier the caller has reached; the client never receives locked figures and only draws the lock.
    Specs must prove: below tier 1 → no city figures; tier 1 → overview only; tier 2 → the detail. A merchant
    company's own investment is irrelevant (the gate is per viewer).
  - The Markets section's drill-down from a good into individual cities follows the same gate (aggregate public,
    per-city rows gated).
- **Threshold values, proposed from prod (decided by default; the owner may reverse):** a share costs 200 🪙 at
  level 0, 320 at level 1, 819 at level 3 (`works_share_price`: `works_cost_base × works_cost_growth^level /
  shares_per_level`); a merchant company's stake per city is p50 22,287 🪙, p90 179,369, max 831,320; NO player
  holds any share yet (0 player rows of 2,859 in `city_shares`); merchants' lap nets (lap ≥ 2, last 24 h) are
  p50 1,071 🪙, p90 31,556. So: **tier 1 = 20,000 🪙** (about one good merchant lap's profit, ~100 shares at
  level 0), **tier 2 = 100,000 🪙** (five times that; above most merchants' stakes). Re-check against the
  economy after the money fix (build 1) lands — it changes what "one good voyage" earns.

### The schema decided so far (not written)

Migration file: `20260818000214_the_world_keeps_its_figures.sql` (0214 while 0212 insurance and 0213 haul cap are
open; **renumber to prod head + 1 at push**; rename the `_0214` suffixes on pg_temp helpers, temp tables and the
probe uuid `00000000-0214-…` with it — `tests/duplication.spec.ts` keys the self-assert tag on the file number).

One job, `public.tick_stats(p_now timestamptz default now())`, scheduled as `byeharu-voyage:stats` every 15
minutes (`*/15 * * * *`), defined INACTIVE like every job since 0078 (`wind_the_clock()` activates what the chain
defines; nothing in the chain starts it). It only READS the game tables and writes only its own four tables, each
keyed by `slot = drift_slot_of(p_now)` (900 s) so a retried run writes 0 rows (ON CONFLICT DO NOTHING, 0013's
idiom):

- `public.stats_world (slot, at, players_ducats, npc_ducats, city_ducats, escrow_ducats, minted, removed, moved,
  volume_sold, volume_bought, flows jsonb)` — one row per slot. `flows` = per-kind sums since the previous row,
  from `treasury_flows` + `treasury_daybook` (today's game day) + ledger kinds not mirrored by a flow.
- `public.stats_good (slot, good_id, index_vs_base numeric, mid_p50, units_sold, units_bought, stock_sum,
  stock_target_sum, markets int)` — one row per good per slot (555 rows) over ALL markets (the public, un-gated
  aggregate). `index_vs_base` = median over the offered pairs of `mid / base_value`.
- `public.stats_city (slot, port_id, purse, income, spending, taxes, works_level_sum, top_buys jsonb, top_sells
  jsonb)` — one row per harbour per slot (238 rows). Gated read.
- `public.stats_city_good (slot, port_id, good_id, mid, stock, stock_target, units_sold, units_bought)` — only for
  pairs that TRADED in the period or are offered (≤ 1,348 + traded), never all 132,090. Gated read (tier 2).
- `public.stats_npc (slot, houses, sailing, docked, laid_up, profit_day, losing_lap_pct, top jsonb, bottom jsonb)`
  — one row per slot; `top`/`bottom` = 5 companies each by `route_earnings` day (name, nation, day, laps).

**Retention in the same job:** 15-min rows for 7 days; older rows compacted to one row per game day (the last slot
of each day kept, the rest deleted) and kept forever. Expected steady size: 7 d × 96 slots × (1 + 555 + 238 +
~1,500) ≈ 1.5 M small rows at most for the city-good table — **measure it on a prod-shaped world (the world image
in PGlite) before fixing the shape; if the city-good table is too heavy, keep only traded pairs and read live
stock from `port_goods` in the RPC instead.**

**Reads (registered in `client_rpc_entry_points()` by one sliced hunk, as 0177 does; `authenticated` only):**
- `world.stats_overview(p_hours int)` — public: the world rows in the window + the latest flows + merchants row.
- `world.stats_markets(p_window text)` — public: every good's latest row with 1 h / 1 d / 7 d change (from the
  compacted rows) and a 24-point sparkline; top risers / fallers / most traded computed server-side.
- `world.stats_city(p_port uuid)` — GATED: tier from `city_shares`; returns `{tier, paid, next_threshold, …}` and
  the figures only for the tier reached; the client draws the lock from `tier`.
- `world.stats_cities()` — the list: every harbour with its tier for the caller (name, flag, tier, paid, needed).
- `world.stats_me()` — the caller's own income/day (compose `world.books`), best trades (own `standing_route_laps`
  / `orders.result`), and the leaderboard by `players.ducats` RANK with names only.

**Self-assert (own probe rows, rolled back):** run `tick_stats` twice in one slot → second writes 0; the world
row's four holders sum to `tick_city`'s `world_ducats` formula recomputed inline; the good index of a planted
market equals `mid / base_value`; a probe company with 0 / tier-1 / tier-2 stakes (through `public.invest_for`, the
one door) gets lock / overview / detail from `world.stats_city`; compaction keeps one row per old day; the registry
+5 and reverses; walls (`client_write_grants`, `client_executable_writers`, `caller_evaluated_functions`) = 0.
**Run its selections read-only on prod before the PR**, and time `tick_stats` on the PGlite world image (target:
well under the arrivals sweep's ~2.7 s; it must not slow arrivals).
