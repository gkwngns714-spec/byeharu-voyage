# 2026-10-31 — the landing city scene is ~8.5× lighter

Owner: *"the game became slow, find this"* (2026-10-31). The City page is the app's landing screen,
so every open paid for the scene it drew.

## Measured before (390×844, headless chromium, 4× CPU throttle, 10 s after ready)

- Scene DOM: **3,299 elements** — 2,853 circles, 178 rects, 31 paths, 132 groups, 60 animateMotion;
  the dot layers alone were teeming 2,198, lights 292, crowd 321 (297 circles + 24 motions), walkers
  72 (36 circles + 36 motions); the whole DOM was 3,436.
- Main thread: **9,743 ms busy of 10,000** (first run) / 10,184 ms (second run); script 158–317 ms,
  layout 112–115 ms; long tasks 1 × 61 ms (first run) / 33 × 1,928 ms (second, loaded machine).
- FPS while the scene animates: 58.5 (first run) / 31.9 (second run); worst frame 66.6 / 100 ms.

## What changed (drawing technique only — the look is identical)

Every stipple speck, window light and still person was its own `<circle>`; at ~2,800 elements the
main thread was saturated repainting them under the SMIL walkers. The same dots are now a few PATHS
of zero-length round-capped strokes (`M x y h0`, stroke-width = 2r), bucketed by radius and opacity:
the source ranges (r 0.35–0.7, opacity 0.1–0.28 for the specks; 2–3 levels of the lights' and
crowd's own ranges) quantize by ≤ 0.06, which is invisible at 240 units.

- Stipple: 2,198 circles → **9 paths**.
- Window lights: 292 circles → **6 paths** (day/night opacity keeps the old curve per bucket).
- Still people: 297 circles → **6 paths**; the 60 people who move (24 strollers + 36 walkers) stay
  individual circles with their own `animateMotion` — unchanged.
- The 33 bastions → **1 path** of rotated rounded squares (identical geometry).
- The per-building and per-ship `<g>` wrappers and the paired fill/outline rects (blocks, market
  square, hall plaza/fountain, inn courtyard) are folded into single elements (identical attributes).

## Measured after (same method)

| | before (two runs) | after (two runs) |
|---|---|---|
| scene elements | 3,299 | **422**, then **390** (with the bastion path) |
| circles / groups / paths | 2,853 / 132 / 31 | 89 / 16 / 53 |
| long tasks in 10 s | 1 (61 ms) / 33 (1,928 ms total) | **0 / 0** |
| main-thread time in 10 s | 9,743 ms / 10,184 ms | 2,918 ms / 7,294 ms |
| FPS | 58.5 / 31.9 | 60.1 / 59.7 |
| worst frame | 66.6 / 100 ms | 16.8 / 33.4 ms |

The machine was heavily loaded for the second before and second after runs (the after run's wall time
was 1.0 m); the deterministic node count and the zero long tasks are the stable signals, and both
main-thread figures are far below both baselines.
