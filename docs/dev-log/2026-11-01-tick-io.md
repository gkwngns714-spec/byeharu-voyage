## What 0289 changes

One hunk in `public.tick_market_drift(timestamptz, uuid)`: its two UPDATE statements become one, each
column group under 0137's own condition, so a row gets **one new version a run instead of two**.
The regeneration's expressions read `stock`, `stock_target`, `base_target`, `production_rate`, `glut`,
`glut_at` — none of the columns the drift group writes — so the merged statement computes the same
values the two produced in sequence. The counts the function returns (`drifted`, `regenerated`) are read
first, under the same two conditions; they feed `tick_market_drift_each_port`'s notice only.

The file asserts (§2) the pre-image hunk occurs exactly once; (§3) every expression appears verbatim,
whitespace-insensitive, in both hunks — drift, the three stock fragments, glut, targets, rate, works,
depth, and the three conditions; (§4) the new body runs on a probe harbour with no rows (`drifted` 0,
`regenerated` 0, no row written); (§5) every other function in public/cmd/world/voyage is md5-unmoved,
the registry count unchanged, both owner switches as found, no wall moved.

**Not touched:** any schedule, cadence, TTL, knob or switch; any other function; no table or column;
no cron. The drift's random draw is the same expression (deliberately not replayable — its sequence is
not a figure).

  `pg_stat_statements`; `n_dead_tup` on port_goods and the last autovacuum; the beat's splits
