## What 0278 does

- **`world.report(p_span text default 'all')`** — NEW, the one read. Derived from the append-only
  `public.ledger` per read, stores nothing (the 0014 rule). Shape exactly as §4: `{total, sections:[{id, word,
  ducats, lines:[{kind, ducats}]}], places:[{kind:'port'|'voyage'|'earlier', …, ducats}], days:[{game_day,
  net}]}`. Span = `'day' | 'week' | 'all'` in GAME days via `world.game_day` (0005, the one clock); the week is
  the last 7 game days (design §7.7 "in game days"), NOT `world.week_of`'s real week — **decision recorded**:
  the design's own default (§7.7) says the spans are in game days, and 0275's week (a real week = 210 game
  days) is a Town Hall key, not a report span. The guard still refuses loudly when `world.week_of` is absent
  (the brief's condition — the chain must carry both clock authorities), and the function never invents a
  second clock.
- **Sections** — the ONE kind→section mapping lives in the function (design §4): Trade (SELL, BUY, TAX) ·
  Crew (WAGES, HIRE) · Supplies (PROVISION) · Repairs (REPAIR) · Insurance (INSURANCE, INSURANCE_PAID) ·
  Invest (SHARE, DIVIDEND, DONATION) · Ships (BUILD) · Other (TUITION, TOW, and any kind not listed, under
  its own name — nothing is dropped). The client maps the served section `id` to EN/KO labels for display
  only; it never knows which kind belongs to which section. `FOUNDING` is capital: excluded, as 0177 did.
- **Places** — one per row: the row's `voyage_id` when it names a live voyage (0277 fills the SAILING voyage,
  else the latest ARRIVED), else its `port_id`, else `'earlier'` (old rows, and the event-less rows — WAGES,
  TAX — 0277's rule leaves nameless). A dangling `voyage_id` (never for a player: 0249's compactor is
  merchant-only) falls through to the port, so no row can vanish from the places. Port rows carry the served
  `code` and `name`; the client prints its own localised port name (`portNameOf`, a label, not a figure).
  Voyage rows carry `from`/`to` codes and the departure game day (the §5 sketch's `LIS→ANR d41`).
- **Days** — zero-filled by the server (the client computes no figure): `'day'` = today, `'week'` = today−6
  .. today, `'all'` = the first non-FOUNDING row's day .. today (empty when there is none).
- **`world.books` is dropped** in the same file — its registry row becomes the report row (one hunk, sliced
  from the live body, reverses, ACL unmoved) and the function is revoked and dropped. **The design's "its only
  caller is Profit.tsx" was stale: `stats/Me.tsx` read it too** (the 7-day bars). Both faces now read
  `world.report('week')` — the figures are the same ones (books(7)'s window = the report week's total; the
  report's zero-filled days replace the client's own zero-fill), so the Stats tab's Me face changes not at all.
  One authority for "what did I earn", not two.

## Ambiguities and decisions (the owner may reverse any)

1. **The report's week = 7 game days** (§7.7 "in game days"), not `world.week_of`'s real week. The guard
   demands `world.week_of` exists (the brief's condition), but the span does not use it.
2. **The design's "its only caller is Profit.tsx" was stale** — `stats/Me.tsx` read the books too; it now
   reads `world.report('week')`, same figures.
3. **`world.books` is dropped, not just de-registered** (the design said "from the registry") — a dead read
   left granted-but-unregistered would be a second authority for the same figures and a wall hazard.
4. **Section lines are always drawn**; there is no tap-to-expand accordion — the hard rule "a press never
   collapses or re-flows" beats §5's "a tap opens its lines", and always-drawn lines satisfy "in place, below
   it, nothing moves" trivially.
5. **Places carry no per-kind lines** — §4's shape has lines only on sections; the desk spec asks only that
   sections and places stand.
6. **WAGES/TAX read "Earlier"** — they have no ref event, so 0277's rule leaves them nameless; the design's
   "every new ledger row has fleet_id" is read as the event-backed rows.
