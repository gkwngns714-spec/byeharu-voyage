# 2026-10-27 — Economy E6: a trade moves the price both ways (owner row 212, `osn-e6-impact`, migration 0254)

> *"i want prices to be moved like stocks"* (owner, 2026-10-26, docs/CLOSED_ECONOMY.md §4)

**Lands DARK** behind `price_impact` (false). Turning it on is the owner's call:
`update public.world_config set value = 'true' where key = 'price_impact'`.

## What it adds

| piece | what |
|---|---|
| the press | `port_goods.glut`, made signed: > 0 price down (sold into), < 0 price up (bought out). Same column, same `× (1 − glut)` term |
| CHECK | `port_goods_glut_check` [0, 0.5] → [−0.5, 0.5] (widened only, added NOT VALID then validated) |
| knob | `price_impact` false |
| `public.price_impact_lit()` | the knob AND `economy_closed()` |
| `public.press_after(glut, units, target, side, per, max)` | the one rule: glut ∓ 0.30 × units / max (buy −, sell +), clamped ±`glut_max` (0.30), 4 places |
| `world.quote_priced` (3 hunks) | lit: each 10-tun shelf priced at the walk's press — a buy's shelf at the press after it, a sale's at the press before it, so buy N then sell N meet every shelf at one mid (0211: a round trip never pays) |
| `cmd.do_buy` (1) | lit: writes the press the walk ended on |
| `cmd.do_sell` (1) | lit: the same mark through the one rule (floored at −0.30); dark: 0194's expression verbatim |
| client | the "why this price" line reads "Bought a lot lately" / "최근 많이 사감" when the press is below 0 |

Decay is unchanged (`tick_market_drift`: glut × 0.5 per game-day); it fades a negative press the same way.

## Decided by default (the owner may reverse)

- Own flag `price_impact`, not lit by the deploy (the economy is already closed, so a gate on `economy_closed()` alone
  would have lit it — the same reason as 0245).
- Step = the existing `glut_per_depth` 0.30; cap = the existing `glut_max` 0.30, both ways.
- §4's "Noise" (drift slot 900 → 600 s, θ 0.932, σ 0.0166) is NOT in this slice: three live knobs, and
  `drift_slot_seconds` is stored in slot units on every row (going 900 → 600 → 900 would freeze drift for months;
  0240's dev-log). It needs its own owner decision.
- The CHECK is widened to ±0.5, not narrowed to ±0.30, so no live row can fail it; the clamp is the rule.
