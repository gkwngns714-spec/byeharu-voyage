## 6. Getting the new machine working

`docs/NEW_MACHINE.md` is the procedure and it is the authority; this is only the short list.

1. `git clone` — **not onto a OneDrive path**; `npm install` dies there ("Exit handler never called").
2. **`git config core.autocrlf false` before anything else.** Migrations are LF-only.
3. **Node 24+ is required, not preferred** — `scripts/db/*` import `.ts` directly and rely on type
   stripping.
4. **Two files cannot travel in the repo** (`.gitignore` ignores `*.local`) and must be copied or
   recreated — not through a chat window:
   * `.env.local` — without it `npm run dev` runs in local PGlite mode; the game works, but it is
     not the online game.
   * `supabase.credentials.local` — without it you cannot push migrations to production.
5. Then read, in this order: `docs/OWNER_REQUESTS.md` (the owner's own words, highest authority) →
   `docs/DESIGN_V1.md` → `docs/WORK_PLAN.md` §4 → `docs/DEV_LOG.md` top entry → `docs/RESUME.md`.
   `docs/NO_SPAGHETTI.md` is the law.
